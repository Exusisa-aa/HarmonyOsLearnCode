# module_analysis.md - 功能模块需求分析

【选择的模块】道具生成与拾取系统（PowerUp System）

【核心职责】
负责管理 7 种道具的生成时机、位置、效果应用和消失逻辑，严格还原原版每 20 辆敌人生成 1 个道具的规则。

【输入】

- 接收参数：已消灭敌人数、当前关卡、道具类型随机种子
- 依赖模块：EntityManager（实体管理）、GameStateManager（游戏状态）、AudioSystem（音效）

【输出】

- 产生结果：生成 IPowerUp 对象、应用道具效果、播放音效
- 交互方式：通过事件总线通知其他模块（如道具拾取事件）

【约束条件】

- 必须遵循 PROMPT_SYSTEM.md - 第 2.1 节命名规范（IPowerUp.ts, PowerUpSystem.ts）
- 性能要求：道具生成耗时 < 5ms，同屏最多 1 个道具
- 禁止使用：禁止在 build 中执行耗时逻辑，禁止频繁创建销毁对象（使用对象池）

【验收标准】

- 需要通过 ACCEPTANCE_TESTS.md 中的 TC008、TC012、TC013 测试用例
- 道具生成时机准确（第 20、40、60...辆敌人）
- 7 种道具效果正确实现（头盔、手榴弹、时钟、星星、船、铲子、枪）
- 持续时间准确（10 秒/20 秒）
- 道具从顶部中央掉落，10 秒未拾取消失

## 技术难点预判

1. **道具生成时机精确控制**：需要准确计数消灭敌人数，跨关卡保持
2. **道具效果持续时间管理**：需要定时器或帧计数，多道具同时存在时的管理
3. **铲子特殊逻辑**：需要临时修改基地周围墙体类型，20 秒后恢复
4. **手榴弹全灭敌人**：需要遍历所有敌人并触发销毁，同时加分
5. **对象池复用**：道具对象需要正确重置状态，避免状态污染
